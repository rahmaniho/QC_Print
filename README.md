# QC Print Inspector

سامانه فارسی و راست‌چین مدیریت کنترل کیفیت چاپ صنعتی؛ شامل سفارش‌ها، بازرسی مرحله‌ای، محاسبه رنگ CIEDE2000، دانسیته/TVI، رجیستر، چسبندگی، بارکد، عیوب، CAPA، داشبورد و خروجی PDF/Excel. این نرم‌افزار ابزار ثبت و تحلیل داده است، نه گواهی‌دهنده مستقل انطباق قانونی.

## قابلیت‌ها

- داشبورد KPI و روند بازرسی‌ها، آخرین سفارش‌ها و عیوب بحرانی
- مدیریت سفارش و مشتری، فایل مرجع PDF/تصویر، فیلتر و صفحه‌بندی
- فرم بازرسی چندمرحله‌ای، اعتبارسنجی Zod و محاسبه ΔE00/ΔE76 در مرورگر و سرور
- ثبت دانسیته و TVI، رجیستر، چسبندگی ASTM D3359، گرید بارکد، عیوب و وضعیت مستندات قانونی
- امتیازدهی شفاف و تصمیم Pass / Conditional / Fail؛ عیب بحرانی یا عدم انطباق قانونی باعث رد می‌شود
- CAPA، استانداردهای مرجع، مدیریت کاربران مبتنی بر نقش و ثبت رویدادهای حساس
- ورود با Credentials، هش bcrypt، JWT، بازیابی رمز ایمیلی با لینک یک‌بارمصرف
- گزارش PDF و Excel چندشیتی و آپلود امن به Vercel Blob
- رابط RTL واکنش‌گرا، فونت Vazirmatn، تم روشن/تیره و نمودارها

## اجرای محلی

نیازمندی‌ها: Node.js 20.19+، pnpm 9، PostgreSQL 14+.

```bash
pnpm install
cp .env.example .env.local
# DATABASE_URL، AUTH_SECRET، ADMIN_EMAIL و ADMIN_PASSWORD را در .env.local مقداردهی کنید.
pnpm prisma migrate deploy
pnpm db:seed
pnpm dev
```

برنامه در `http://localhost:3000` اجرا می‌شود. برای ساخت رمز امن:

```bash
openssl rand -base64 32
```

Seed فقط وقتی اجرا می‌شود که `ADMIN_PASSWORD` یکتا با حداقل ۱۲ نویسه تنظیم شده باشد. هیچ رمز پیش‌فرض یا حساب کاربریِ قابل‌ورود در کد قرار نگرفته است. سفارش‌های `SAMPLE-*` صرفاً داده نمایشی‌اند و نباید به‌عنوان داده کنترل کیفیت واقعی استفاده شوند.

## معماری و ملاحظات کیفیت

- مسیرهای API در `src/app/api` احراز هویت، کنترل نقش، اعتبارسنجی Zod، بررسی Origin برای درخواست‌های تغییردهنده، rate limit برای endpointهای عمومی و AuditLog دارند.
- مرز امتیازها و تلورانس‌های پیش‌فرض برنامه تنظیمات شروع کارند، نه حدود جهان‌شمولی که خود استانداردها برای همه فرایندها الزام کنند. مرجع قراردادی، بستر، دستگاه، شرایط اندازه‌گیری و نسخه استاندارد را برای هر سفارش ثبت کنید.
- `NOT_APPLICABLE` باید فقط وقتی انتخاب شود که واقعاً الزام تماس غذایی/قانونی وجود ندارد. وضعیت `PENDING` امتیاز/تصمیم را محافظه‌کارانه مشروط می‌کند.
- ارزیابی مهاجرت، ایمنی تماس غذایی، کمپوست‌پذیری یا ادعای قانونی به گزارش آزمایشگاه و مدارک تأمین‌کننده نیاز دارد؛ صرفاً از ظاهر چاپ قابل نتیجه‌گیری نیست.
- Rate limit در این نسخه با PostgreSQL اتمیک و کلید IP/مسیر اعمال می‌شود. برای استقرار پرترافیک پشت پراکسی‌های سفارشی، هدر IP قابل اعتماد را محدود کنید و حدها را متناسب با سازمان بازبینی کنید.

## استقرار Vercel

مراحل کامل متغیرهای محیطی، پایگاه داده، Blob، ایمیل، migration و ساخت مدیر در [راهنمای استقرار](./README.md#راهنمای-استقرار) آمده است. Vercel نمی‌تواند بدون اتصال PostgreSQL و Secretهای اختصاصی، پایگاه داده و حساب امن را به‌صورت جادویی ایجاد کند؛ این وابستگی‌های بیرونی یک‌بار باید در داشبورد Vercel تأمین شوند.

### راهنمای استقرار

1. پوشه پروژه را به مخزن GitHub خود push کنید و در Vercel با **New Project** آن را Import کنید.
2. در Neon یا Vercel Marketplace یک PostgreSQL بسازید؛ مقدار pooled `DATABASE_URL` را در Vercel برای Production, Preview و Development ثبت کنید.
3. در **Settings → Environment Variables** مقدارهای `AUTH_SECRET` (خروجی مستقل `openssl rand -base64 32`)، `NEXTAUTH_URL` و `NEXT_PUBLIC_APP_URL` را تنظیم کنید. روی Vercel، آدرس عمومی پروژه را وارد کنید. Secret را بین محیط‌ها یا پروژه‌ها مشترک نکنید.
4. برای آپلود فایل، یک Vercel Blob Store متصل و `BLOB_READ_WRITE_TOKEN` را تنظیم کنید. برای بازیابی رمز، Resend را تنظیم کرده و `RESEND_API_KEY` و `EMAIL_FROM` تأییدشده را اضافه کنید.
5. اولین migration باید پیش از استفاده از نسخه جدید روی دیتابیس اجرا شود: `pnpm db:migrate` با `DATABASE_URL` همان محیط. در استقرار اولیه، این فرمان را از محیط CI/محلی امن اجرا کنید یا یک مرحله‌ی migration کنترل‌شده در pipeline خود قرار دهید؛ آن را همزمان از چند build موازی اجرا نکنید.
6. مدیر اول را یک‌بار ایجاد کنید:

   ```bash
   read -rsp 'رمز یکتای مدیر: ' ADMIN_PASSWORD && echo
   ADMIN_EMAIL='admin@your-company.com' ADMIN_NAME='مدیر کیفیت' ADMIN_PASSWORD="$ADMIN_PASSWORD" pnpm db:seed
   unset ADMIN_PASSWORD
   ```

   Seed داده‌های نمونه و استانداردها را نیز وارد می‌کند. رمز مدیر از env خوانده و با bcrypt هش می‌شود؛ رمز `Admin@123` عمداً به‌عنوان پیش‌فرض ناامن استفاده نشده است.

7. Push به branch متصل‌شده، build خودکار Vercel را آغاز می‌کند. بعد از هر تغییر schema، migration جدید بسازید، آن را بررسی و commit کنید و پیش از ترافیک production اجرا کنید.

> **نکته:** «دیپلوی یک‌کلیکی بدون هیچ تنظیمی» برای اپ دارای دیتابیس، ارسال ایمیل و فضای فایل ممکن نیست؛ اتصال این سرویس‌ها و secrets باید توسط مالک پروژه تنظیم شود. هیچ secret را در Git یا گفتگو قرار ندهید.
